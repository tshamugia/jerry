# CLAUDE.md

Jerry is a fast, keyboard-first file manager for Windows 10/11 (x64). It works on real Windows files next to Explorer, not instead of it. Tauri 2 shell, Rust core, React UI.

These rules are binding. If a task seems to need breaking one, stop and ask; never diverge silently. Keep this file current when the structure or a rule changes.

## Decided, do not revisit

- **Stack is final:** Tauri 2 · Rust stable, edition 2024, `windows` crate · tokio · rayon · rusqlite (bundled, WAL) + rusqlite_migration · thiserror · tracing · tauri-specta · React 19 · TypeScript strict · Vite · Tailwind CSS 4 · Radix UI (shadcn/ui model) · lucide-react · Zustand 5 · TanStack Virtual 3 · cmdk + uFuzzy · dnd-kit. Don't propose other frameworks or swap libraries. Adding any dependency not in the Tech PRD needs the user's OK.
- **Platform:** Windows 10 22H2+ and Windows 11, x64 only. No ARM64, macOS or Linux.
- **English-only UI**, no i18n library. Georgian file names must fully work (render, natural sort, ZIP UTF-8 names).
- **Out of scope** (PRD, minimalism): cloud APIs and FTP, sync and backup, built-in editors, tags and color labels, encryption, RAR/7z creation, plugins, translations.

## Architecture rules

1. **The UI never touches the file system.** All IO runs in Rust on background threads: IO pool, Shell STA pool (2–4 threads, with timeouts), one transfer worker per physical disk or network server, rayon for search and sort. Never block the main thread or the tokio runtime with IO.
2. **Tauri lockdown.** Capabilities expose only Jerry's own commands, plus `core:event:allow-listen` and `allow-unlisten` so the page hears Jerry's events. Never add the `fs`, `shell` or `http` plugins. CSP allows only `self`, `icon:`, `thumb:` and the asset protocol: no `eval`, inline scripts or remote URLs. DevTools only in dev builds. `decorations: false`, `dragDropEnabled: false`.
3. **IPC has four channels:** commands (`invoke`), streams (Tauri `Channel`) for listing and search, events (`emit`) to all windows, custom protocols (`icon://`, `thumb://`, asset) for binary data. All types come from Rust via tauri-specta into `src/ipc/bindings.ts`; regenerate with `pnpm bindings` and commit the result. A new command gets `#[tauri::command]` + `#[specta::specta]` and goes into the `commands!` list in `src-tauri/src/lib.rs` (dev-panel commands only into its debug arm); one that can fail returns `Result<T, JerryError>`, does IO through `jobs::background` and main-thread work through `jobs::on_main`. The UI imports it from `src/ipc`, never from `bindings.ts`. tauri-specta v2 is a release candidate: `specta`, `specta-typescript` and `tauri-specta` stay `=`-pinned and are bumped together. Listing batches are binary little-endian columns, one `ArrayBuffer` per batch through a `Channel` (the `Bytes` type); sort orders go as binary `u32` arrays (ADR-0001). Progress events at most 10 per second.
4. **Paths stay in Rust.** Core keeps the exact `OsString` path; the UI refers to files by `entry_id` or a core-issued path token, and gets path text only for display. Never rebuild an operation's path from a JS string. Core uses `\\?\` long paths; the manifest is `longPathAware`.
5. **Errors are codes, not text.** Rust returns one shape, `JerryError { code, path, params }` (`AccessDenied`, `NotFound`, `InUse`, `NoSpace`, `InvalidName`, `DeviceGone`, `NoRecycleBin`, `Cancelled`, `Os`, and `Internal` for Jerry's own bugs such as a panicked job). The UI turns the code into English text from `src/strings/` and always offers a next step (Retry, Skip, Show in Explorer).
6. **COM rules live in `jerry-win`.** OLE, clipboard, drag & drop and the native context menu run on the main STA thread; other Shell calls run on the Shell pool with timeouts, so one bad shell extension can't freeze Jerry. The one exception is opening files in their programs (`ShellExecuteExW`, `jerry_win::open`): each request gets a short-lived STA thread of its own, because a program that answers by DDE (AutoCAD with a DWG) takes seconds to start and would hold up a pool worker, and with it icons. Main-thread work goes from an `async` command through `run_on_main` to Jerry's own message-only window, never through Tauri's `run_on_main_thread`, which holds back events during modal loops (ADR-0002).
7. **Drag & drop and clipboard use Windows OLE only**, inside Jerry and with other apps. dnd-kit is only for reordering inside Jerry (tabs, favorites, transfer queue).
8. **One SQLite file** (`%APPDATA%\Jerry\jerry.db`) holds all persistent data: WAL, versioned migrations, file backup before migrating. Rust owns it; the UI changes it through commands and hears `settings:changed`. Undo history lives in memory only. No disk caches of our own (icons cached in memory, thumbnails come from Windows' thumbcache). Logs via tracing to `%LOCALAPPDATA%\Jerry\logs`, 14-day rotation.
9. **Network only for the update check** (can be turned off). No telemetry, no other requests.
10. **Never admin.** Manifest `asInvoker`, registry writes only under HKCU, per-user NSIS install.
11. **Panics don't kill the app.** `panic = "unwind"` stays in release; background workers wrap each job in `catch_unwind`, log the panic and fail only that job.

## Data safety rules

Every file operation must follow these. A change that weakens one is wrong even if tests pass.

1. The source is deleted only after a complete, verified copy exists at the destination.
2. Files are written as `name.ext.jerrypart` (hidden) and renamed to the final name only when complete.
3. A file replaced by Replace goes to the Recycle Bin.
4. Undo touches only unchanged files (file ID, size and modified time must match); changed files are skipped with a reason.
5. An operation the Recycle Bin can't protect (network, USB, long paths) warns first.
6. Deleting or moving system folders (Windows, Program Files, the Users root) needs extra confirmation.
7. Jerry never deletes a file without a user action. The only exception is its own `.jerrypart` files, found through the transfer journal.

Also: never read the content of a cloud-only OneDrive file without a user action (thumbnails use `SIIGBF_INCACHEONLY`). Symlinks and junctions aren't followed by default and are loop-checked by volume and file ID. Copying a folder into itself is blocked (`GetFinalPathNameByHandleW`). ZIP extraction blocks `..` and absolute paths. The transfer journal records a job before it starts.

## UI rules

- Layout, sizes and colors match the design; behavior and shortcuts match the PRD.
- Colors, sizes and density come from `design/tokens.css` (`--jerry-*`) mapped into Tailwind's `@theme` in `src/app/styles.css`. Tailwind's default colors, type sizes, radii and shadows are removed, so only token names exist (`bg-mica`, `bg-pane`, `text-fg-2`, `text-small`, `h-row`, `h-titlebar`, `rounded-ctrl`, `shadow-flyout`). No hard-coded colors or one-off sizes in components; a missing size goes into `@theme` first.
- The accent color is only for selection, progress, focus and the active-pane bar.
- File lists are virtualized (TanStack Virtual) with fixed row heights per density (30 / 24 px); row components are memoized so a selection change repaints only changed rows.
- One command registry (id, title, default shortcut, context, handler) feeds the palette, menus, toolbar, settings and the F1 table. Shortcuts match `KeyboardEvent.code`, so they work on the Georgian layout. WebView2 browser accelerators are off.
- All user-visible text lives in `src/strings/`. Dates `DD.MM.YYYY HH:mm` by default, numbers and sizes through `Intl`, `tabular-nums` for numbers.
- File content never runs script: SVG only through `<img>`, Markdown without raw HTML, pdf.js with `isEvalSupported: false`.
- The window is created hidden, with the theme background (no white flash), and shown after the first render: `App` calls `commands.appReady()` once the settings and the Windows appearance are in and the frame is committed; Rust shows the window anyway after 5 s if that never comes. Theme, density, accent and Mica are attributes on `<html>` (`src/app/appearance.ts`); the tokens do the rest.

## Code conventions

Formatting follows `.editorconfig` and `.gitattributes`: LF everywhere except `.ps1`/`.bat`/`.cmd` (CRLF); 2-space indent, 4 for Rust.

**Rust**
- `cargo fmt` and `cargo clippy --all-targets -- -D warnings` clean.
- Errors through thiserror, logging through tracing. No `println!` or `dbg!` in committed code.
- No `unwrap()`/`expect()` on IO, OS or IPC results outside tests; propagate a `JerryError`.
- Every `unsafe` block has a `// SAFETY:` comment.
- Workspace lints (`Cargo.toml` → `[workspace.lints]`, `clippy.toml`) enforce the above: `unwrap_used`, `expect_used`, `print_*`, `dbg_macro` and `undocumented_unsafe_blocks` warn outside tests and fail CI. Every crate has `[lints] workspace = true`.
- `src-tauri/build.rs` embeds `jerry.exe.manifest` through the linker into every target, so tests and examples that link Tauri get Common Controls v6 too (without it they die with `STATUS_ENTRYPOINT_NOT_FOUND`).

**TypeScript**
- `strict` on, no `any`, Biome for lint and format, `tsc --noEmit` clean.
- Feature code stays in its `features/<name>/` folder; only shared building blocks go to `ui/`. App state lives in Zustand stores.

## Testing

- Core behavior gets tests: Rust unit and integration tests with cargo-nextest on `tempfile` folders, covering Georgian names, long paths and locked files where they apply. proptest for "operation + Undo = original tree"; criterion benchmarks for listing, sorting and search.
- UI: Vitest + Testing Library for stores, keymap, filter, selection and the rename table. E2E: WebdriverIO + tauri-driver.
- OLE drag & drop, clipboard, OneDrive and network drives are checked by hand with checklists in `docs/checklists/`, once per phase.
- Tests never touch real user folders, only temp folders.

## Workflow

- One issue per session, in the order of the current epic's task list. Issues that don't depend on each other (no "დამოკიდებულია" link) and don't touch the same files may run in parallel sessions, each in its own worktree and branch. Spikes (#11–#18) live on `spike/*` branches and don't merge into `main`; their results go into the Tech PRD.
- One branch per issue from `main`, named `<type>/<issue>-<slug>` (for example `chore/7-dev-env`). One PR per issue with `Closes #N`.
- Conventional Commits in English: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `chore`, `ci`.
- An issue is done when its "მზადაა, როცა" (acceptance) items are verified, not just when its checklist is ticked.
- **A PR is opened only when the work is finished and tested locally:** `pnpm check` is green (rustfmt, clippy, Biome, `tsc`, Vitest, nextest), `pnpm bindings` leaves no diff, and the acceptance items are verified, including the manual ones the user confirmed. No draft or work-in-progress PRs.
- **Once the PR is open, merge it right away** (merge commit, no review or CI wait) and delete the branch on GitHub and locally: `gh pr merge <n> --merge --delete-branch`. The local checks are the gate; CI still runs on the PR and on `main` as a safety net, and if it turns red, the fix comes next in its own PR.
- If issues are added or reordered, update the epic's task list too.
- `/ship` (`.claude/skills/ship/SKILL.md`) runs these steps at the end of an issue: checks, acceptance, commit, push, PR, merge. Keep it in step with this section.

## Releases

- SemVer. The one version is `version` in `[workspace.package]` of the root `Cargo.toml`; Tauri and the installer take it from there.
- To release `X.Y.Z` (or a pre-release such as `X.Y.Z-rc.1`): on a `chore/release-vX.Y.Z` branch, set the version, run `pnpm changelog --tag vX.Y.Z` and commit `Cargo.toml`, `Cargo.lock` and `CHANGELOG.md` as `chore(release): vX.Y.Z`. Open and merge the PR as usual, then tag the merge commit on `main` and push the tag (`git tag vX.Y.Z`, `git push origin vX.Y.Z`). The tag publishes a Release, so ask the user before pushing it.
- `workflows/release.yml` checks the tag against `Cargo.toml` and `CHANGELOG.md`, builds the NSIS installer and publishes the Release with that version's changelog section as its notes. A tag with a pre-release part makes a GitHub pre-release, which the updater never offers.
- A release that fails or turns out broken is fixed in a new PR and released as the next version (or the next `rc`). A pushed tag is never moved.
