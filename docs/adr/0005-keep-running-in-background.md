# ADR-0005: Jerry ფონზე რჩება

- **სტატუსი:** მიღებულია, 03.11.2026 (მომხმარებლის გადაწყვეტილება)
- **წყარო:** spike #1 ([#11](https://github.com/tshamugia/jerry/issues/11#issuecomment-6565323519), branch `spike/11-cold-start`), [PR #110](https://github.com/tshamugia/jerry/pull/110); PRD «Windows-თან ინტეგრაცია»; Tech PRD «წარმადობა», «რისკები და კითხვები»

## კონტექსტი

PRD-ის მიზანი: Jerry იხსნება 1 წამზე ნაკლებში. Spike #1-ში Jerry-ის საკუთარი ნაწილი თბილ გაშვებაზე ~0.5 წმ-ია, აქედან ~70 % WebView2-ის დაყენებაა. Hybrid GPU-იან ლეპტოპზე (Intel + NVIDIA) WebView2-ის GPU პროცესი მძინარე NVIDIA-ს აღვიძებს, და ეს პირველ კადრს +0.4–1.45 წმ-ს უმატებს (~1.9 წმ). Chromium-ის ფლაგები (`--disable-gpu`, swiftshader, warp და სხვა) და Windows-ის "Power saving" ვერ შველის. დამალული, მზა ფანჯრის ჩვენებას 19–56 ms სჭირდება.

## გადაწყვეტილება

- პარამეტრი "Keep Jerry running in the background", ნაგულისხმევად ჩართული: ბოლო ფანჯრის დახურვა Jerry-ს მალავს და არ თიშავს. ბრძანება "Exit Jerry" სრულად თიშავს. გამორთული პარამეტრით დახურვა თიშავს.
- v0.1-ში: დახურვა = დამალვა + ერთი ეგზემპლარი (#43). v1.0-ში: დამალული გაშვება Windows-თან ერთად (#85).
- ფანჯარა ჩნდება React-ის პირველი commit-ის შემდეგ. ფანჯარასა და WebView2-ს ფონი თემიდან აქვს, Rust-ში, ფანჯრის შექმნამდე.

## შედეგები

- პირველის შემდეგ ყოველი გახსნა მყისიერია.
- Jerry მუდმივად იკავებს ~120 MB-ს (ბიუჯეტი: დამალული Jerry < 150 MB).
- პირველი ცივი გაშვება hybrid GPU-ზე ~1.9 წმ რჩება; desktop-ზე და მხოლოდ ინტეგრირებულ GPU-ზე ~0.5 წმ-ია.
- სრულად გათიშვას ცალკე ბრძანება სჭირდება, რადგან დახურვა აღარ თიშავს.

## განხილული ალტერნატივები

- **(ა) ~1.9 წმ ბიუჯეტის გამონაკლისად:** ყოველდღიურ გამოყენებაში ყოველ გახსნაზე ~2 წამი.
- **`--disable-gpu`:** ~35 MB-ს ზოგავს, მაგრამ სიჩქარეს არ ცვლის, software compositing კი scroll-ზე რისკია.
- **Tray აიკონი:** PRD-ში არ არის (მინიმალიზმი).
